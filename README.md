# fastinstall

Bootstrap-скрипты для быстрого разворачивания базового окружения на новой
машине — macOS и Linux (apt/dnf/pacman/zypper/apk): zsh + oh-my-zsh, tmux
(oh-my-tmux) + tpm с плагинами (tmux-sensible, tmux-resurrect,
tmux-continuum, tmux-yank, tmux-thumbs, tmux-fzf, tmux-fzf-url,
catppuccin-tmux, tmux-sessionx, tmux-floax), neovim, mc, vifm, alacritty, git, ssh,
stow, htop, eza, pass/gnupg, rust, uv, omp-manager (Oh My Posh). Сами
dotfiles (личные конфиги) —
отдельный репозиторий; этот проект только ставит и обновляет
пакеты/инструменты, на которые эти конфиги рассчитаны, включая `stow`,
которым тот репозиторий раскладывает свои конфиги. Neovim IDE
(AstroNvim/NvChad/LunarVim, с возможностью снести и попробовать другую
сборку) — по выбору: `./tools-extra.sh ide`.

## Структура

```
setup.sh          — установка базового набора пакетов
samba-share.sh    — быстрое расшаривание каталога по SMB (macOS/Linux)
tools-extra.sh    — доп. TUI/CLI-инструменты (yazi, bat, lazygit, k9s, ...)
tui-tools.sh      — семейство tui-tools для администрирования Linux-сервера
lib/              — общие shell-хелперы (common.sh, packages.sh, tools_extra.sh, tui_select.sh)
PACKAGES.md       — подробный список пакетов, которые ставит setup.sh
TOOLS-EXTRA.md    — описание каждого инструмента из tools-extra.sh
```

## Быстрый старт

```bash
git clone <repo-url> ~/fastinstall
cd ~/fastinstall
./setup.sh
```

Скрипт определяет ОС и пакетный менеджер, ставит базовый набор пакетов и
делает zsh оболочкой по умолчанию (`chsh`), печатает, что осталось сделать
руками (если что-то не удалось поставить автоматически). После первого
запуска перезапустите терминал (или `exec zsh`), чтобы подхватить zsh/tmux.

Свои dotfiles разворачивайте отдельным репозиторием поверх уже установленных
этим скриптом инструментов.

## Использование

### setup.sh

```bash
./setup.sh        # TUI-диалог выбора пакетов, затем установка выбранного
./setup.sh --all  # установить всё без диалога выбора (-y — короткая форма)
```

Базовые предпосылки (Homebrew/flatpak, curl, git) ставятся всегда, до
диалога — без них не работает ничего остального. Дальше — классический
синий чекбокс-список (ncurses `dialog`, как в debconf/dpkg-reconfigure,
Clonezilla live или установщике Ubuntu Server): стрелки — перемещение,
Пробел — отметить/снять пункт, Enter — установить отмеченное, Esc/Cancel —
отмена; печатать номера руками не нужно. `dialog` при первом обращении
ставится автоматически (пакет есть в apt/dnf/pacman/zypper/apk и в
Homebrew); если поставить не удалось — тихий откат на пронумерованный
список без стрелок. Без TTY (например, запуск из другого скрипта) диалог
пропускается, ставится всё.

### samba-share.sh

Быстро поднимает общую сетевую папку (SMB/Samba) для каталога — на Linux
через пакет `samba` (секция в `smb.conf`, `smbd`/`nmbd`), на macOS через
штатную утилиту `sharing`. Идемпотентен — "запустил и забыл": повторные
запуски с тем же именем шары добавляют пользователей или ничего не делают,
а не пересоздают всё заново.

```bash
./samba-share.sh [опции] [путь-к-папке]
./samba-share.sh -d -n ИМЯ                 удалить шару ИМЯ целиком (только Linux)
./samba-share.sh -x -n ИМЯ -u ЮЗЕР         убрать доступ ЮЗЕР к шаре ИМЯ (только Linux)

  -n, --name ИМЯ         имя шары; путь необязателен — если не указан,
                         каталог создаётся в /srv/samba/ИМЯ (macOS:
                         /Users/Shared/ИМЯ), либо берётся у уже
                         существующей шары с этим именем
  -u, --user ЮЗЕР        кому дать доступ (по умолчанию — текущий пользователь;
                         для -x/--remove-user умолчания нет, обязательно)
  -p, --password ПАРОЛЬ  пароль Samba, ставится неинтерактивно (без TTY и без
                         этой опции создание пароля пропускается)
  -g, --guest            разрешить гостевой доступ без пароля
  -r, --readonly         общий доступ только на чтение
  -d, --delete           удалить шару -n ИМЯ целиком (только Linux)
  -x, --remove-user      убрать доступ -u ЮЗЕР к шаре -n ИМЯ, не трогая
                         саму шару и остальных её участников (только Linux)
  -h, --help              эта справка
```

На macOS тумблер "File Sharing" в System Settings и первичное подтверждение
пароля Apple не даёт включить из терминала — скрипт выведет точную
подсказку, что доделать руками.

**На Linux каждая шара живёт в своей unix-группе** (`smbshare-ИМЯ`), а доступ
в `smb.conf` прописан как `valid users = @smbshare-ИМЯ` — поэтому добавить
ещё одного пользователя к уже существующей шаре можно, просто запустив
скрипт заново с тем же `-n` и новым `-u`/`-p`: `smb.conf` при этом не
трогается, пользователь просто попадает в группу шары.

Если пользователь из `-u`/`--user` не существует, скрипт создаёт его сам —
строго SMB-only учётку (`useradd -M -N -G smbshare-ИМЯ -s <nologin>`): без
домашнего каталога, без входа по SSH/консоли. Системного пароля у такой
учётки нет — пароль для Samba ставится отдельно через `smbpasswd` (см.
`-p`/`--password` выше), после чего можно сразу подключаться по SMB.

Каталог шары принадлежит `root:smbshare-ИМЯ` (владелец — не конкретный
пользователь: реальный доступ и так через группу). Для негостевых шар права
каталога — `2770` (`rwxrws---`) — доступ строго владельцу и группе, у
остальных пользователей системы (даже с локальным шеллом на этой машине, не
по SMB) нет вообще никакого доступа, включая просмотр содержимого. Для
гостевых шар (`-g`) права остаются `2775`, т.к. гостевое подключение в Samba
маппится на отдельную unix-учётку (обычно `nobody`), не состоящую в группах
шар.

**Удаление шары** (`-d -n ИМЯ`) убирает секцию из `smb.conf` и группу шары. У
каждого участника группы членство в ней убирается всегда; пользователь
удаляется целиком, только если одновременно: у него шелл-заглушка
(`nologin`/`false`, то есть это SMB-only учётка, созданная скриптом) И не
осталось доступа ни к одной другой шаре (в этом случае вычищается и его
запись в базе Samba, `smbpasswd -x`). Пользователь с обычным логин-шеллом не
удаляется никогда — только вычищается его членство в группе этой шары.
Файлы на диске не удаляются — путь к ним выводится в конце.

**Убрать доступ одного пользователя** (`-x -n ИМЯ -u ЮЗЕР`), не трогая саму
шару и остальных её участников — та же логика удаления учётки, что и выше,
но применённая только к одному пользователю: он просто выходит из группы
шары, а удаляется целиком лишь при том же условии (SMB-only шелл и нет
доступа к другим шарам).

### tools-extra.sh

Ставит дополнительные TUI/CLI-инструменты, не входящие в базовый набор
`setup.sh` (yazi, bat, lazygit, k9s, dust, bottom и т.д. — полный список с
описанием каждого в [TOOLS-EXTRA.md](TOOLS-EXTRA.md)). macOS и Linux
(apt/dnf/pacman/zypper/apk); там, где пакета нет в системном менеджере —
`cargo install` (нужен `rust`, его ставит `setup.sh`) или бинарь с GitHub
Releases.

```bash
./tools-extra.sh                # TUI-диалог выбора инструментов
./tools-extra.sh --all          # поставить все инструменты без диалога
./tools-extra.sh bat yazi lnav  # поставить только перечисленные
./tools-extra.sh --list         # список с описаниями, ничего не ставить
```

Диалог выбора — тот же, что и в `setup.sh` (см. выше); при явном
перечислении инструментов в аргументах диалог не показывается. Без TTY
ставятся все инструменты.

### tui-tools.sh

Ставит семейство [tui-tools](https://github.com/tui-tools) — TUI для
администрирования Linux-сервера: firewall (ufw/firewalld/nftables), systemd,
снапшоты (snapper), сеть, аудит защищённости, пользователи, обновления,
диски, ssh, логи, cron, сертификаты, контейнеры, samba. **Только Linux** —
на macOS этих инструментов нет (проект целится именно в Linux-серверы).

```bash
./tui-tools.sh                  # поставить все 14 инструментов
./tui-tools.sh firewall users   # поставить только перечисленные
./tui-tools.sh --list           # список с описаниями, ничего не ставить
```

Каждый инструмент показывает точную команду перед тем, как её выполнить
(preview-confirm-run) — сама установка ничего в системе не меняет. Но
`tui-firewall`, `tui-users`, `tui-cron` и `tui-secure` умеют менять
firewall, пользователей и cron, поэтому при использовании внимательно
читайте, что предлагается выполнить, прежде чем подтверждать.

## Требования

- bash, git
- sudo (или запуск от root) для шагов, требующих привилегий — на системах
  без sudo и не под root часть шагов помечается как "сделать вручную"

`stow` этим скриптом ставится сам (см. [PACKAGES.md](PACKAGES.md)) — не как
зависимость самого fastinstall, а заранее, для отдельного dotfiles-репозитория.

## Если шаг упал с ошибкой

Все шаги `setup.sh` идемпотентны (уже установленное просто пропускается) —
если что-то упало, чаще всего достаточно **перезапустить `./setup.sh`**.
Сетевые шаги (git clone, oh-my-zsh, omp-manager) сами делают 3 попытки с паузой,
но на только что поднятой машине сеть иногда не готова дольше — тогда
просто запустите скрипт ещё раз. В конце работы скрипт печатает, что упало
(`FAILED_STEPS`) и что нужно сделать руками (`MANUAL_TODO`).

Если видите `No space left on device` при `cargo install` (omp-manager,
tools-extra.sh) — это про диск/`/tmp`, а не про сеть или конфигурацию.
`cargo install` при неудачной сборке не подчищает за собой временный каталог
в `/tmp/cargo-install*` (каждый раз новое случайное имя), и на маленьком
диске несколько подряд неудачных сборок (особенно тяжёлые крейты вроде
`yazi`, `termscp`, `termusic`, `gpg-tui`) быстро съедают всё место — после
чего валится вообще всё, вплоть до самых маленьких крейтов. Начиная с этой
версии `cargo_install_clean()` (`lib/common.sh`) подчищает эти каталоги
до и после каждой попытки, но если `/tmp` уже забит от прошлых прогонов,
сначала освободите место руками: `rm -rf /tmp/cargo-install*` и проверьте
`df -h /tmp`.
