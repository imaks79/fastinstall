# Обзор всех пакетов и инструментов

Сводка того, что ставят `setup.sh`, `tools-extra.sh` и `tui-tools.sh`, одним
файлом и сгруппировано по смыслу — чтобы удобнее было решить, что оставить,
что убрать, что заменить. Это справочный файл для чтения/редактирования
списков в `lib/packages.sh` и `lib/tools_extra.sh`, сам он ни на что не
влияет и не выполняется.

Условные обозначения: **[core]** — `setup.sh` (базовая установка, диалог
по умолчанию ставит всё), **[extra]** — `tools-extra.sh` (опционально, по
одному через диалог/аргументы), **[tui]** — `tui-tools.sh` (только Linux,
администрирование сервера).

## 3. Zsh/tmux-экосистема **[core]**

- **oh-my-zsh** + плагины `zsh-autosuggestions`, `zsh-syntax-highlighting`
- **oh-my-tmux** — готовый конфиг tmux
- **tpm** (менеджер плагинов tmux) + плагины: `tmux-sensible`, `tmux-resurrect`,
  `tmux-continuum`, `tmux-yank`, `tmux-thumbs`, `tmux-fzf`, `tmux-fzf-url`,
  `catppuccin-tmux` (тема), `tmux-sessionx`, `tmux-floax`

⚠️ **Возможное пересечение**: `tmux-sessionx` и `tmux-fzf` оба дают
fzf-подобный выбор/переключение сессий/окон — на практике достаточно одного
из них, но оба ставятся без вопроса.

> Оставь без изменений.

## 5. Файловые менеджеры — 3 штуки на одну задачу

| Пакет    | Откуда  | Стиль                                                      | Заметка                               |
| -------- | ------- | ---------------------------------------------------------- | ------------------------------------- |
| **mc**   | [core]  | классический Norton Commander (2 панели, F-клавиши)        | самый привычный/старый                |
| **vifm** | [core]  | vim-раскладка клавиш, тоже 2 панели                        | альтернатива mc для vim-пользователей |
| **yazi** | [extra] | Rust, async, превью изображений/PDF/архивов, самый быстрый | самый современный вариант             |

> Готово: `chafa`/`pdftoipe`/`7zip` убраны как отдельные пункты меню.
> `yazi` теперь ставится строго по официальной доке
> (yazi-rs.github.io/docs/installation/: нативный пакет/apt-репозиторий/
> copr/cargo-фолбэк в зависимости от системы), а все Optional Dependencies
> оттуда (ffmpeg, 7-Zip non-standalone, jq, poppler, fd, ripgrep, fzf,
> zoxide, resvg, ImageMagick, xclip/wl-clipboard) ставятся автоматически
> вместе с ним, без отдельных пунктов — см. `install_yazi()`/
> `install_yazi_deps()` в `lib/tools_extra.sh` и раздел
> [TOOLS-EXTRA.md](TOOLS-EXTRA.md#yazi--опциональные-зависимости).

| `df`                | **duf**                               | наглядные точки монтирования                                                                                           |

## 7. Логи и отладка

| Пакет        | Откуда  | Фокус                                                         |
| ------------ | ------- | ------------------------------------------------------------- |
| **lnav**     | [extra] | просмотр/анализ файлов логов, SQL-запросы по логам            |
| **gonzo**    | [extra] | realtime-логи в k9s-стиле, нативная поддержка Kubernetes/OTLP |

Три инструмента закрывают разные сценарии (файлы логов вообще / потоковые
структурированные логи и k8s / именно journald на сервере), пересечение

> Без изменений.

## 8. Git / Docker / Kubernetes TUI **[extra]**

- **lazygit** — TUI для git
- **lazydocker** — TUI для docker/docker-compose
- **k9s** — TUI для Kubernetes-кластера

Независимы друг от друга, пересечения нет — ставить по факту использования

> Без изменений.

## 9. SSH и сеть — сильное пересечение, кандидат на прополку **[extra]**

| Пакет        | Что делает                                                                           |
| ------------ | ------------------------------------------------------------------------------------ |
| **lazyssh**  | TUI для SSH-подключений в стиле lazydocker/k9s                                       |
| **keyward**  | управление SSH-*ключами*, `~/.ssh/config`, аудит безопасности, шифрованные бэкапы    |

> Готово: `ssh-list` и `sshs` полностью убраны из `TOOLS_EXTRA_NAMES`
> (дублировали `lazyssh`), в `tools-extra.sh` из этой группы остались
> только `lazyssh` и `keyward` (последний не дублирует остальные — он про
> сами ключи и аудит, а не про подключение).

Остальное сетевое:

- **vortix** — TUI для WireGuard/OpenVPN: телеметрия, kill switch, DNS/IPv6-утечки
- **wlctl** — TUI для wifi/ethernet/vpn через NetworkManager (только Linux)
- **termscp** — терминальный SCP/SFTP/FTP/S3-клиент (замена FileZilla/WinSCP в TUI)
- **gpg-tui** — управление ключами GnuPG (надстройка над `gnupg` из core)

> Без изменений.

## 11. Языки и инструменты разработки **[core]**

- **rust** (`rustup`) — нужен как фолбэк-сборщик для многих `[extra]`-пакетов без нативных пакетов (`cargo install`)
- **uv** — менеджер Python-пакетов/окружений (уже современная замена связки pip+venv+pyenv/poetry)
- **[Oh My Posh](https://ohmyposh.dev/)** — движок темы шелла; brew tap на macOS, официальный `install.sh` на Linux

> Готово: **omp-manager** (TUI-мастер настройки Oh My Posh) переехал из
> `setup.sh` в **[extra]** — `./tools-extra.sh omp-manager`. Сам Oh My Posh
> (движок) остался в `setup.sh`, по инструкции с ohmyposh.dev — только
> бинарь, без правки `.zshrc`.

## 12. Neovim IDE — взаимоисключающий выбор **[extra] `./tools-extra.sh ide`**

- **AstroNvim**
- **NvChad**
- **LunarVim**
- пункт «очистить редактор» — сносит конфиги/данные/кэш всех трёх сразу

AstroNvim и NvChad физически ставятся в один и тот же `~/.config/nvim`,
поэтому одновременно может быть только один из двух; LunarVim независим
(`~/.config/lvim`). Это единственная группа, где выбор одного пункта явно
подразумевает "не остальные два" — уже реализовано диалогом, просто держите
в уме при редактировании.

> Оставь без изменений.

## 13. tui-tools.sh — администрирование Linux-сервера **[tui]** (только Linux)

14 независимых бинарников с GitHub Releases (не через системный пакетный
менеджер), каждый — preview-confirm-run перед изменением системы:

| Инструмент     | Область                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| tui-firewall   | ufw/firewalld/nftables                                                                                        |
| tui-systemd    | юниты systemd: что упало и почему                                                                             |
| tui-snapper    | снапшоты Btrfs/LVM                                                                                            |
| tui-network    | интерфейсы, маршруты, соединения                                                                              |
| tui-secure     | аудит защищённости сервера                                                                                    |
| tui-users      | пользователи и группы                                                                                         |
| tui-update     | обновления пакетов                                                                                            |
| tui-disk       | диски и точки монтирования                                                                                    |
| tui-ssh        | конфигурация и активные сессии SSH (серверная сторона — отличается от клиентских ssh-list/lazyssh/sshs из §9) |
| tui-logs       | системные логи (journald + файлы)                                                                             |
| tui-cron       | задания cron и systemd-таймеры                                                                                |
| tui-cert       | TLS-сертификаты                                                                                               |
| tui-containers | контейнеры Docker/Podman                                                                                      |
| tui-samba      | шары, учётки и live-подключения Samba                                                                         |

Это отдельное семейство от Homebrew/apt-мира — риск здесь не "лишний
пакет", а то, что `tui-firewall`/`tui-users`/`tui-cron`/`tui-secure` умеют
менять live-конфигурацию сервера, если согласиться с предложенной командой.

## Сделано (было в "Что нужно изменить")

- `./setup.sh --list` и `./tools-extra.sh --list` — список всех программ с
  описанием, языком реализации и ссылкой на первоисточник (git-репозиторий,
  либо сайт разработчика, если репозитория нет).
- `tools-extra.sh`: `ssh-list` и `sshs` убраны совсем, из SSH-группы
  остались только `lazyssh` и `keyward`.
- `yazi` ставится строго по https://yazi-rs.github.io/docs/installation/;
  `pdftoipe`, `7zip`, `chafa` убраны как отдельные пункты меню — вместо них
  все Optional Dependencies официальной доки (ffmpeg, 7-Zip non-standalone,
  jq, poppler, fd, ripgrep, fzf, zoxide, resvg, ImageMagick,
  xclip/wl-clipboard) ставятся автоматически вместе с `yazi`, без отдельных
  пунктов.
- `./setup.sh --list` / `./tools-extra.sh --list` — добавлен пункт
  "поддерживаемая ОС" (macOS + Linux / только macOS / только Linux) к
  каждой программе.
- **alacritty** (сам терминал) переехал из `setup.sh` (`[core]`) в
  `tools-extra.sh` (`[extra]`, `install_alacritty()` в `lib/tools_extra.sh`).
  `alacritty-theme` по уточнению осталась в `setup.sh`
  (`install_alacritty_theme()` в `lib/packages.sh`), отдельным шагом — не
  зависимостью alacritty, в отличие от того, как это сделано для `yazi`.
- **omp-manager** (TUI-мастер настройки) переехал из `setup.sh` (`[core]`) в
  `tools-extra.sh` (`[extra]`, `install_omp_manager()` в
  `lib/tools_extra.sh`). Вместо него в `setup.sh` появился сам
  **[Oh My Posh](https://ohmyposh.dev/)** (движок темы шелла,
  `install_oh_my_posh()` в `lib/packages.sh`) — строго по официальной доке
  ohmyposh.dev/docs/installation/: brew tap на macOS, `install.sh` на
  Linux; только бинарь, без правки `.zshrc`.
